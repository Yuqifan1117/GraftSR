The module is organized into four logical layers around the DiffSynth `QwenImagePipeline`:
- `model_inference/` and `model_inference_low_vram/`: one-shot Python entry points per task (text-to-image, edit, inpaint, ControlNet variants, distillation, EliGen, layered control). Low-VRAM variants add a `vram_config` dict that drives disk/CPU offload and float8 eager loading.
- `model_training/`: training harness built on `DiffusionTrainingModule`. `train.py` defines `QwenImageTrainingModule`, which constructs the pipeline, splits units for LoRA/full training, and dispatches tasks (`sft`, `direct_distill`, data processing) through a `task_to_loss` map. Subdirectories `full/` and `lora/` contain per-task `.sh` launchers plus Accelerate configs; `special/` groups NPU, fp8, low-vram, split, and differential-training experiments; `validate_*` mirrors inference scripts for evaluation.
- Top-level Python modules implement custom components: `generator.py` and `generator_edit.py` wrap the pipeline with DualLoRA and condition-type embeddings; `base.py` provides `BaseModelForT2ILoRA` with LoRA checkpoint saving; `discriminator.py`, `ganloss.py`, `dinov3loss.py`, `metrics.py` supply GAN/Diffusion loss building blocks used by `train_gan*.py`; auxiliary utilities cover dataset sampling, region selection, post-processing search, and naturalization.
- `configs/` holds YAML experiment configs (learning rates, GAN weights, pixel losses, scheduler settings) consumed by the GAN training scripts.
Dependency direction is one-way: examples import from `diffsynth.pipelines.qwen_image` and `diffsynth.core`; internal modules only depend on each other and DiffSynth, never on higher-level project code.
