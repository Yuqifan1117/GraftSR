The module is organized into three top-level subdirectories mirroring the model lifecycle:
- `model_inference/` and `model_inference_low_vram/`: standalone Python scripts that instantiate `ZImagePipeline.from_pretrained` with `ModelConfig` entries pointing to HuggingFace model IDs and safetensor file patterns; the low-vram variant mirrors each script with memory-conscious settings.
- `model_training/`: a unified entry point `train.py` defining `ZImageTrainingModule`, which subclasses `DiffusionTrainingModule` from `diffsynth.core` and wires up tasks (`sft`, `direct_distill`, `trajectory_imitation`) through a `task_to_loss` dispatch table. Shell scripts under `full/`, `lora/`, and `special/` invoke this trainer via `accelerate launch` with corresponding YAML configs (`accelerate_config.yaml`, `accelerate_config_zero3.yaml`).
- `special/` contains niche training variants: `differential_training/`, `npu_training/`, and `trajectory_imitation/`, each with its own `.sh` launcher and optional `validate.py` helper.
Dependency direction is one-way: example scripts import from `diffsynth.pipelines.z_image` and `diffsynth.core`; there are no cross-imports between inference and training scripts.
