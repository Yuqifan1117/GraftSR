The module is organized into three top-level example directories under `examples/ernie_image/`:
- `model_inference/`: minimal one-shot inference scripts that instantiate `ErnieImagePipeline.from_pretrained` with `ModelConfig` entries pointing to PaddlePaddle HuggingFace model IDs for transformer, text encoder, VAE, and tokenizer.
- `model_inference_low_vram/`: same inference API but adds a `vram_config` dict per sub-model specifying offload/onload/preparing/computation dtype and device, plus a `vram_limit` argument to `from_pretrained` for CPU offloading.
- `model_training/`: a unified `train.py` entry point defining `ErnieImageTrainingModule(DiffusionTrainingModule)` which wraps the same `ErnieImagePipeline`, splits trainable units via `split_pipeline_units`, and dispatches tasks (`sft:data_process`, `sft`, `sft:train`) through a `task_to_loss` map. Full fine-tuning is driven by `full/ERNIE-Image.sh` launched via `accelerate launch --config_file accelerate_config_zero3.yaml` (DeepSpeed ZeRO Stage 3, bf16, 8 processes). LoRA fine-tuning is driven by `lora/ERNIE-Image.sh` with `--lora_base_model dit` and target modules. Validation scripts in `validate_full/` and `validate_lora/` mirror the training pipeline for evaluation.

Dependency direction is one-way: examples import from `diffsynth.pipelines.ernie_image` and `diffsynth.core` / `diffsynth.diffusion`; there are no cross-dependencies between inference and training scripts.
