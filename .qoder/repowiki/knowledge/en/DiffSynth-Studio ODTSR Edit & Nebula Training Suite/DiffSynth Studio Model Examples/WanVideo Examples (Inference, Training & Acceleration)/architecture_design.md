The module is organized into four top-level subdirectories that separate concerns by use case:
- `model_inference/` and `model_inference_low_vram/`: one self-contained Python script per model variant (T2V, I2V, Fun, VACE, S2V, Animate, etc.), each loading `WanVideoPipeline.from_pretrained` with a `ModelConfig` list describing the diffusion, tokenizer, and VAE components, then calling the pipeline and saving the output video.
- `model_training/`: a single entry point `train.py` defines `WanTrainingModule(DiffusionTrainingModule)` which wraps `WanVideoPipeline`, applies LoRA or full-parameter fine-tuning, and dispatches tasks (`sft`, `direct_distill`, data processing) through a `task_to_loss` map. Subfolders mirror the same naming scheme as inference scripts: `full/` and `lora/` contain `.sh` launch scripts plus shared `accelerate_config_*.yaml` files; `special/` groups niche setups (fp8, low-vram, NPU, split training, direct distillation); `validate_full/` and `validate_lora/` reuse the inference scripts to evaluate checkpoints.
- `acceleration/`: provides a distributed sequence-parallel example (`unified_sequence_parallel.py`) using `use_usp=True` in `WanVideoPipeline.from_pretrained` and `torch.distributed` to save outputs only from rank 0.

Dependency direction is strictly outward toward `diffsynth.pipelines.wan_video.WanVideoPipeline` and `diffsynth.core` utilities; the examples never modify the library itself. Each `.sh` script follows a uniform pattern: download dataset via `modelscope download`, then `accelerate launch --config_file ... train.py` with explicit `--dataset_base_path`, `--dataset_metadata_path`, resolution, model IDs, and `--trainable_models` flags.
