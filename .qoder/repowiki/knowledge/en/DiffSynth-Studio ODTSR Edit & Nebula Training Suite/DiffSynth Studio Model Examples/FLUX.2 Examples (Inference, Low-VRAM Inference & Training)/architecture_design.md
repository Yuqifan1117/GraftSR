The module is organized into three top-level example categories, each mirroring the same set of model variants (dev, klein-4B/9B, klein-base-4B/9B):
- `model_inference/` — single-file Python scripts that instantiate `Flux2ImagePipeline.from_pretrained` with a list of `ModelConfig` entries (text_encoder, transformer, vae, tokenizer) and run prompt-based generation plus optional image editing.
- `model_inference_low_vram/` — identical scripts but tuned for constrained GPUs: offload_dtype/onload_dtype use float8 or disk, and `vram_limit` is computed from `torch.cuda.mem_get_info` to cap memory usage.
- `model_training/` — a shared `train.py` entry point that subclasses `DiffusionTrainingModule`, builds a `Flux2ImagePipeline`, splits pipeline units via `split_pipeline_units`, and dispatches tasks (`sft:data_process`, `direct_distill:data_process`, `sft`, `direct_distill`) through a `task_to_loss` map and a `launcher_map`. Full-parameter training uses `accelerate_config.yaml` (DeepSpeed ZeRO-2) and `.sh` launchers; LoRA training scripts pass `--lora_base_model dit` and explicit `--lora_target_modules`; NPU-specific scripts live under `special/npu_training/`; validation scripts under `validate_full/` and `validate_lora/` mirror the training variants.
Dependency direction is one-way: examples import from `diffsynth.pipelines.flux2_image` and `diffsynth.core.UnifiedDataset`; no code in this module is imported by library code.
