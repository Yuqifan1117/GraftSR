The module is organized into three top-level example categories under `examples/joyai_image/`: `model_inference/` (standard GPU inference), `model_inference_low_vram/` (VRAM-constrained inference with CPU offloading), and `model_training/` (training pipeline). All examples consume the same `diffsynth.pipelines.joyai_image.JoyAIImagePipeline` and `ModelConfig` API, loading a triad of models — transformer, JoyAI-Image-Und weights, and Wan2.1 VAE — from the `jd-opensource/JoyAI-Image-Edit` repository via `origin_file_pattern`. The training entry point `model_training/train.py` defines a `JoyAIImageTrainingModule` subclassing `DiffusionTrainingModule`, which wires up data loading through `UnifiedDataset`, loss computation via `FlowMatchSFTLoss`, and task dispatch (`sft:data_process`, `sft`, `sft:train`) through a `launcher_map`. Full-parameter training uses two-stage shell scripts: first a data-caching pass, then actual training launched via `accelerate launch` with a DeepSpeed ZeRO-3 config (`accelerate_config_zero3.yaml`). LoRA training follows the same two-stage pattern but targets specific attention modules (`img_attn_qkv,txt_attn_qkv,img_attn_proj,txt_attn_proj`) with rank 32. Validation scripts in `validate_full/` and `validate_lora/` load trained checkpoints directly into the pipeline's `dit` unit or via `pipe.load_laro()` respectively.
