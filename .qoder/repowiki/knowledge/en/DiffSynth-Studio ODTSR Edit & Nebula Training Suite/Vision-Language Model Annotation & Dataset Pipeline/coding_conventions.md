- Each orchestrator script defines a top-level class (e.g. `Annotator`, `ImageCaptioner`) that takes a `Client` instance in its constructor and uses `client.format_user_content()` + `client.chat()` to invoke models, keeping prompt construction separate in `prompts.py`.
- All LLM responses are post-processed through `client.parse_json()`, which first tries `json.loads` and then falls back to extracting content wrapped in ```json ... ``` markdown blocks.
- Model selection follows a convention where dashscope-native models are listed in `DEFAULT_DASHSCOPE_MODELS` and routed through `dashscope_chat`, while others go through `openai_chat`; the `api_provider` parameter on `Client` selects the default provider.
- Cost and token usage are tracked per-call by passing a `usage_id` string to every `chat`/`multi_modal_embed`/`generate_image_*` call, with results accumulated in `self.usages[usage_id]` and `self.total_costs[usage_id]`.
- Bounding-box outputs from VLMs are normalized to the model's internal input size and then rescaled back to original image coordinates via `resize_vlm_bboxes` / `resize_vlm_elements` before being used downstream.
- Prompt templates are stored as module-level string constants and grouped by task (filtering, detection, captioning) with explicit output schema comments, and a `SEMANTIC_PROMPT_STYLES` registry maps style names to `{keys, prompt}` pairs.
