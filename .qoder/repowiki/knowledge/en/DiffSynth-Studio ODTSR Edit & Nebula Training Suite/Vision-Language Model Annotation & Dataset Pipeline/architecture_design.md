The module is organized as a flat collection of Python scripts plus shared utilities:
- `client.py` provides the single `Client` class that abstracts calls to both OpenAI-compatible APIs and Alibaba DashScope (via `dashscope` SDK), handling multimodal message formatting, token usage/cost tracking, JSON parsing, embedding, and image generation.
- `prompts.py` centralizes all prompt templates (filtering, reference selection, object detection, semantic region detection, tile description, captioning) and exposes a `SEMANTIC_PROMPT_STYLES` registry for switching between v1/v2 detection schemas.
- `image_utils.py` holds low-level image I/O helpers: Qwen25VL-aware smart resizing, bounding-box coordinate rescaling back to original dimensions, base64 encoding, download, crop, compression, and extension detection.
- `convert_utils.py` contains dataset-conversion helpers: minimum-side checks, prompt-file generation, and image validation/copying with failure reason tracking.
- Orchestrator scripts (`annotate.py`, `image_caption.py`, `align_ref_to_hq.py`, `annotate_semantic_regions.py`, `backfill_prompts.py`, `backfill_similarity.py`, `generate_simulated_lq.py`, `generate_tile_prompts.py`, `get_item_info.py`) each instantiate a `Client`, pick a model from `DEFAULT_DASHSCOPE_MODELS`, and call the appropriate prompt template through `client.chat()` / `format_user_content()`. Results are parsed via `parse_json` and written out as JSON/TXT/CSV.
- Conversion scripts (`convert_to_train_dataset.py`, `convert_to_test_dataset.py`, `convert_csv_to_realworld_testset.py`) consume annotation JSONs and produce standardized training/test directories (`img/`, `prompt/`) using `convert_utils`.
- Shell entry points (`annotate_test.sh`, `annotate_train.sh`, `image_caption.sh`, `convert_annotation_to_dataset.sh`, `convert_csv_to_realworld_testset.sh`) wrap the Python scripts with fixed argument sets.
Dependency direction is one-way: orchestrators → client/prompts/image_utils/convert_utils; no cross-imports between orchestrators.
