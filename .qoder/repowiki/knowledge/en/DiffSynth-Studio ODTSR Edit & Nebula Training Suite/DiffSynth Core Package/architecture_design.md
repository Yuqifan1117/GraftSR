The package is organized as a flat namespace with five cooperating sub-packages: `core/` provides foundational primitives (attention, data, device abstraction, gradient checkpointing, VRAM offloading); `models/` implements concrete PyTorch model classes; `pipelines/` composes encoders, DiTs, VAEs and schedulers into end-to-end generation workflows; `diffusion/` supplies the training harness, flow-matching schedulers and loss functions; `utils/` holds cross-cutting helpers (ControlNet annotators, LoRA, state-dict converters, xfuser parallelism); `extensions/` adds Real-ESRGAN-style enhancement modules; and `configs/` declaratively maps model classes to weights, converters and VRAM strategies. Children communicate through shared model class names registered in `configs/model_configs.py` and `configs/vram_management_module_maps.py`, which are consumed by the VRAM-aware loader in `core/loader/` and the model factory in `models/model_loader.py`. The top-level `__init__.py` re-exports only `core.*`, keeping the public surface minimal while internal modules import each other directly.
