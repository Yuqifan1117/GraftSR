The module is a pure data-driven configuration layer with three files. `model_configs.py` defines per-series lists (`qwen_image_series`, `wan_series`, `flux_series`, `flux2_series`, `ernie_image_series`, `z_image_series`, `ltx2_series`, `anima_series`, `mova_series`, `joyai_image_series`) where each entry is a dict describing a model variant via keys `model_hash`, `model_name`, `model_class`, optional `state_dict_converter`, and optional `extra_kwargs`; these lists are concatenated into the single `MODEL_CONFIGS` export. `vram_management_module_maps.py` provides two structures: `VRAM_MANAGEMENT_MODULE_MAPS` (a mapping from fully-qualified model class paths to sub-module-to-wrapping-layer dicts, e.g. `torch.nn.Linear -> AutoWrappedLinear`) and `VERSION_CHECKER_MAPS` (version-dependent updaters like `QwenImageTextEncoder_Module_Map_Updater`). `__init__.py` re-exports only `MODEL_CONFIGS`, `VRAM_MANAGEMENT_MODULE_MAPS`, and `VERSION_CHECKER_MAPS`, making this package the single import surface for model registration and VRAM policy lookup. There is no runtime logic beyond the version-checker functions; the dependency direction is one-way outward to `diffsynth.models.*` and `diffsynth.core.vram.layers.*`.
