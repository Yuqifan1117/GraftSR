Three cooperating components built on top of `flux_dit` transformer primitives:
- `FluxControlNet` (`flux_controlnet.py`) is a `torch.nn.Module` that mirrors the Flux DiT structure (joint `FluxJointTransformerBlock`s and single `FluxSingleTransformerBlock`s) and injects per-block linear `controlnet_res_stack` / `controlnet_single_res_stack` projections whose outputs are later aligned to the original 19+38 block layout via `align_res_stack_to_original_blocks`. It accepts optional mode embedding (`processor_id` → `controlnet_mode_embedder`) and additional input channels (`additional_input_dim`).
- `MultiValueEncoder` / `SingleValueEncoder` (`flux_value_control.py`) encode scalar or batched scalar values through `TemporalTimesteps` plus an MLP, adding a learned positional embedding; `MultiValueEncoder` concatenates multiple such encoders.
- `FluxLoRALoader` / `GeneralLoRALoader` / `LoraMerger` / `FluxLoraPatcher` (`flux_lora_patcher.py`) provide two paths: direct weight injection by matching `.lora_A/.lora_B` keys against model modules, and a gated merging path where each target module name maps to a `LoraMerger` that combines base and LoRA outputs through sigmoid-gated LayerNorms. State-dict converters handle Diffusers↔Civitai key renaming and alpha inference.
Dependency direction: all three files depend only on sibling modules (`flux_dit`, `general_modules`, `core.loader`) and never on each other, keeping the ControlNet, value encoding, and LoRA machinery decoupled.
