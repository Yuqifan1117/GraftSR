Three independent utilities under `diffsynth/models/`:
- `general_modules.py` defines stateless functions (`get_timestep_embedding`) and `torch.nn.Module` subclasses (`TemporalTimesteps`, `DiffusersCompatibleTimestepProj`, `TimestepEmbeddings`, `RMSNorm`, `AdaLayerNorm`) that are imported by higher-level model components. `TimestepEmbeddings` supports both a standard Sequential projector and a `DiffusersCompatibleTimestepProj` path controlled by `diffusers_compatible_format`, and can optionally add an embedding conditioned on `addition_t_cond`.
- `model_loader.py` exposes a `ModelPool` class that discovers models by hashing the file against `MODEL_CONFIGS`, dynamically imports the declared `model_class` and optional `state_dict_converter` via `importlib`, and delegates actual loading to `core.loader.load_model`. When VRAM offloading is enabled it builds a `module_map` from `VRAM_MANAGEMENT_MODULE_MAPS` (or falls back to `AutoWrappedModule`) so that selected submodules are wrapped for memory management.
- `tiler.py` implements a `TileWorker` class whose `tiled_forward` composes `tile` → `tiled_inference` → `untile` using `torch.nn.Unfold`/`Fold` and `einops.rearrange` to split a `(B,C,H,W)` tensor into overlapping tiles, run a user-supplied `forward_fn` per tile batch, and reassemble with a cosine-weighted border mask.

Dependency direction is one-way: `model_loader.py` depends on `..core.loader`, `..core.vram`, and `..configs`; `general_modules.py` and `tiler.py` have no intra-module dependencies and are consumed by other parts of the codebase.
