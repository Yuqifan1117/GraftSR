Three independent PyTorch `nn.Module` files plug into the Wan DiT backbone (`wan_video_dit`):
- `wan_video_image_encoder.py` implements a self-contained CLIP-like architecture (VisionTransformer + TextTransformer/XLM-RoBERTa) with helper classes (`SelfAttention`, `AttentionBlock`, `XLMRoberta`, `XLMRobertaCLIP`) and exposes `WanImageEncoder.encode_image()` which runs the visual branch only, returning intermediate features via `use_31_block=True`. Pretrained weights are lazily downloaded through `sora.DOWNLOAD_TO_CACHE`.
- `wan_video_mot.py` defines `MotWanModel` and `MotWanAttentionBlock` that wrap an existing `DiTBlock` from `wan_video_dit`. Each injected block computes a parallel MOT stream (`x_mot`) whose Q/K/V are RoPE-rotated and concatenated with the main stream before `flash_attention`, then gated back. Frequency tensors are precomputed per frame/height/width via `compute_freqs_mot`.
- `wan_video_animate_adapter.py` provides `WanAnimateAdapter` composed of a pose patch embedding, a `Generator` (appearance + motion encoder), a `FaceEncoder` (causal conv stack), and a `FaceAdapter` (multi-layer cross-attention fuser). It hooks into the DiT via two entry points: `after_patch_embedding` to add pose/motion tokens and `after_transformer_block` to inject residual motion features every 5th block.
Dependency direction is one-way: these modules import from `wan_video_dit` but are not imported by it, keeping them as optional adapters.
