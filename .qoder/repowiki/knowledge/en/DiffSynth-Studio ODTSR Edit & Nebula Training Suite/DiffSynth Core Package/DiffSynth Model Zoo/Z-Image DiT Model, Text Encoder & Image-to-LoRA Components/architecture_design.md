Three cooperating modules form the Z-Image generation stack:
- `z_image_dit.py` defines the core `ZImageDiT` transformer built from `ZImageTransformerBlock` units that combine an `Attention` module (with RMSNorm on q/k, RoPE via `RopeEmbedder`, and a custom `attention_forward` from `..core.attention`) with a gated SiLU-gating FeedForward. It supports two modes: basic `[x, cap]` sequence and omni mode `[cap, x, siglip]` with optional SigLIP features. Patching/unpatching is handled by `patchify_and_embed`, `patchify_controlnet`, and `unpatchify`, all respecting `SEQ_MULTI_OF=32` padding. A separate `TimestepEmbedder` provides ADALN conditioning, and per-token noisy/clean modulation is selected via `select_per_token`. Gradient checkpointing is enabled through `_supports_gradient_checkpointing`.
- `z_image_text_encoder.py` wraps a `Qwen3Model` (0.6B/4B/8B variants via `Qwen3Config`) as `ZImageTextEncoder`, exposing the model directly through a thin `forward`.
- `z_image_image2lora.py` generates LoRA weights for the DiT's `layers`, `context_refiner`, and `noise_refiner` submodules. `ZImageImage2LoRAModel` uses `LoRATrainerBlock` with `ImageEmbeddingToLoraMatrix` to produce `(prefix.layer_id.name.lora_A/B.default.weight)` entries; `ZImageImage2LoRAModelCompressed` compresses this into a `ModuleDict` of `ImageEmb2LoRAWeightCompressed` predictors keyed by flattened layer names.
Dependency direction: both text encoder and LoRA components depend only on shared `..core` utilities and each other indirectly through the DiT's submodule naming convention; the DiT itself depends on `general_modules.RMSNorm`, `core.attention`, `core.device.npu_compatible_device`, and `core.gradient`.
