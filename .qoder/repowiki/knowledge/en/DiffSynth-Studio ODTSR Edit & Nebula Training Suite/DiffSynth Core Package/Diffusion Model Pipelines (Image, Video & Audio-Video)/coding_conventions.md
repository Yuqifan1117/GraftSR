- Every pipeline subclass follows the same shape: `__init__` declares `scheduler`, model attributes, `in_iteration_models`, `units` list of `PipelineUnit` instances, `model_fn`, and `compilable_models`; `from_pretrained` is a static factory using `download_and_load_models` + `model_pool.fetch_model`; `__call__` runs `unit_runner` over units then loops `scheduler.timesteps` with `cfg_guided_model_fn` and `self.step`.
- Each processing stage is implemented as a `PipelineUnit` subclass whose `process` method takes `(pipe, ...args)` and returns a dict of output parameters; input/output parameter names are declared via `input_params`, `output_params`, `input_params_posi`, `input_params_nega`, and `seperate_cfg` flags.
- Models are lazily loaded into device inside unit `process` methods via `pipe.load_models_to_device(self.onload_model_names)` rather than upfront, keeping VRAM usage minimal during the unit chain.
- Negative prompt handling is expressed by setting `seperate_cfg=True` on prompt embedder units and providing both `input_params_posi` and `input_params_nega` mappings so the base pipeline can build positive/negative branches automatically.
- Optional auxiliary modules (ControlNet, IP-Adapter, LoRA patcher, value controller, Nexus-Gen, Step1x connector) are attached only when `model_pool.fetch_model(<key>)` returns non-None, keeping the core pipeline functional without them.
