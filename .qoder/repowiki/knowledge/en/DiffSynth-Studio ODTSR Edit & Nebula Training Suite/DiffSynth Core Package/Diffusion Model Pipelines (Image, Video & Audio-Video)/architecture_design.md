Each file defines a single `*Pipeline` class inheriting from `BasePipeline` in `..diffusion.base_pipeline`. The pipeline pattern is uniform: `__init__` sets the `FlowMatchScheduler`, declares model attributes (`text_encoder`, `dit`, `vae_*`, optional `controlnet`, `ipadapter`, etc.), registers an ordered `self.units` list of `PipelineUnit` subclasses, assigns a `model_fn` closure, and marks which models are loaded per iteration via `in_iteration_models` and `compilable_models`. `from_pretrained` is a static factory that calls `download_and_load_models(model_configs, vram_limit)`, then `model_pool.fetch_model(<key>)` to attach each component. The `__call__` method runs the unit chain via `self.unit_runner(unit, self, inputs_shared, inputs_posi, inputs_nega)`, then iterates scheduler timesteps calling `self.cfg_guided_model_fn(self.model_fn, cfg_scale, ...)` and stepping with `self.step(...)`. Post-processing decodes latents through VAEs and returns PIL images or tensors. Video/audio-video pipelines (Wan, LTX2, Mova) extend this with `post_units`, multi-stage denoising (`denoise_stage`), and additional time/patchifier components. Optional features like LoRA merging, VRAM management, NPU patches, and Unified Sequence Parallel (`enable_usp`) are wired as pipeline methods rather than separate classes.
