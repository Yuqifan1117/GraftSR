The module is organized into three cooperating layers with a clear dependency direction: `layers.py` defines the public API (`AutoTorchModule`, `AutoWrappedModule`, `AutoWrappedNonRecurseModule`, `AutoWrappedLinear`) and the recursive `enable_vram_management` / `enable_vram_management_recursively` entry points that walk a model tree and replace matching `torch.nn.Module` subclasses with VRAM-aware wrappers. `initialization.py` provides the `skip_model_initialization` context manager that monkey-patches `torch.nn.Module.register_parameter` to place newly registered parameters on a meta device, enabling zero-alloc model construction. `disk_map.py` implements `DiskMap`, a lazy, buffer-throttled reader over one or more safetensors files (with a fallback `SafetensorsCompatibleBinaryLoader` for `.pt`/`.bin` via `torch.load`) that exposes a `state_dict`-like interface and tracks cumulative parameter count to periodically close/reopen file handles. The wrapper classes maintain an internal `state` machine (0=offloaded, 1=onloaded, 2=preparing) and support per-stage dtype/device configuration (`offload_*`, `onload_*`, `preparing_*`, `computation_*`). Disk offloading is triggered when `offload_dtype == 'disk'`, in which case parameters are materialized on-demand through `DiskMap` rather than moved to another device. FP8 linear paths are gated by `enable_fp8` based on `computation_dtype`.
