The module is organized around a `BasePipeline` (base_pipeline.py) that defines a composable `PipelineUnit` graph: each unit declares its input/output parameter names, and `PipelineUnitGraph.split_pipeline_units` builds an edge/chains graph to separate model-related computation from preprocessing. `DiffusionTrainingModule` (training_module.py) wraps a pipeline into a trainable `torch.nn.Module`, exposing helpers for LoRA injection via PEFT (`inject_adapter_in_model`), VRAM/offload configuration parsing, data device transfer, and splitting units for `:train` vs `:data_process` tasks. The actual training loop lives in `runner.py` through `launch_training_task` and `launch_data_process_task`, which use `accelerate.Accelerator` for DDP/DeepSpeed, AdamW + ConstantLR, gradient accumulation via `accelerator.accumulate`, and optional DeepSpeed activation checkpointing. `flow_match.py` implements a `FlowMatchScheduler` dispatching among FLUX/Wan/Qwen-Image/FLUX.2/Z-Image/LTX-2/lightning/ERNIE timestep schedules, with per-timestep training weights. `loss.py` provides SFT losses (`FlowMatchSFTLoss`, `FlowMatchSFTAudioVideoLoss`), direct distillation, and a `TrajectoryImitationLoss` (teacher-student trajectory alignment using LPIPS). `logger.py` (`ModelLogger`) checkpoints only trainable parameters via `export_trainable_state_dict`. `parsers.py` supplies reusable `argparse` sub-parsers for dataset/model/training/output/LoRA/gradient/general configs. Dependency direction is one-way: runner → training_module → base_pipeline; schedulers and losses are pure utilities consumed by higher layers.
